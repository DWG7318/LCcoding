> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inside the existing LCCoding Worker conversation to implement this plan task-by-task. Do not use superpowers:subagent-driven-development or any subagent. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement LCCoding 2.8.0 as a four-phase, Runtime-neutral Agent-native method with a required Operations Agent, optional Calabash-governed Product Agent, strict dual-Agent isolation, final production topology, `PRODUCT`/`OPERATIONS` Feature Slices, safe 2.7 migration, minimal read-only BI projection, and no new lifecycle/runtime authority.

**Architecture:** `SPEC.md` remains the sole semantic authority. Platform-neutral closed contracts define Agent configuration, deterministic actions, production topology, and Runtime Adapter attestation; existing Feature Slice, status, Verification, security, Delivery, and BI surfaces consume those identities. Twenty-two committed Tasks keep each normal change at eight or fewer non-hash paths and one independently reviewable commit; one zero-write preflight Task and separately authorized release/deployment Cells complete the sequence.

**Tech Stack:** Markdown and strict JSON contracts/templates, Python 3 validators and mutation tests, the existing single compatibility JSON, Rust/Tauri strict readers and sanitized projection, React/TypeScript DTO/DOM/visual tests, PowerShell package/release verification, Git exact-byte integrity, GitHub Actions formal installer release.
