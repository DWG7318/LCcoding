# LCCoding 3.0.0 Real User Journey Acceptance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade LCCoding and its built-in React/Vite/Tauri BI from 2.8.0 to a five-phase 3.0.0 lifecycle with a real-browser, screenshot-backed Real User Journey Acceptance phase before Delivery Preparation.

**Architecture:** `SPEC.md` remains the sole semantic authority. A new exact 3.0 status family adds `REAL_USER_JOURNEY_ACCEPTANCE`, one candidate-bound acceptance summary, a stable `40001+` defect ledger, and a new phase gate. Python validators and copy-on-write migration own project truth; the BI consumes a versioned compatibility asset and projects exact 2.8/four-phase or 3.0/five-phase snapshots without writing project data. The existing UI language and 300×480 desktop shell remain; the implementation adds the fifth phase and one protected summary report, not a redesign.

**Tech Stack:** Markdown contracts/templates, JSON, Python 3 validators/tests, React 19, TypeScript 7, Vite 8, Vitest, Playwright, Rust 2024, Tauri 2, PowerShell 5.1/7, NSIS, Git/GitHub Actions.

---

## Fixed decisions

- Target version is exactly `3.0.0`.
- Phase order is exactly `INITIAL`, `PRODUCT_FORMATION`, `REAL_PRODUCT_INTEGRATION`, `REAL_USER_JOURNEY_ACCEPTANCE`, `DELIVERY_PREPARATION`.
- Phase 4 uses the visible product surface. Code, DOM, API, logs, and prior automated tests may diagnose a defect but cannot replace screenshot-backed visible evidence.
- Each post-repair Phase-4 round restarts from the home page and reruns the complete required journey graph.
- Defect IDs start at `40001` and are never recycled.
- Correction priority is `UI → Workflow → Backend/Core`; one correction may span layers when the root cause requires it.
- Codex viewport preparation may ask the Owner only to expand the right panel and press `F11`; the Agent still performs and judges the product journey.
- The BI stays read-only, preserves its current visual language, supports exact 2.8 and 3.0 shapes, and gains one fifth-phase summary plus one protected journey report.
- Actual installation, tag creation, GitHub Release creation, global Skill deployment, and migration of an external project are outside this implementation plan.
