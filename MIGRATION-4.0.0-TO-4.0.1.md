# Migration: LCCoding 4.0.0 to 4.0.1

This governance patch changes the method and application release identity, not project or BI data protocols. Existing 4.0.0 project status, service topology, receipts, and evidence remain compatible and need no migration. The 4.0.1 Canonical Manifest is accepted with the unchanged 4.0.0 status adapter.

Ponytail remains an external Skill considered only after one recorded Owner inquiry and affirmative project-scoped authorization. Earlier tags, Releases, assets, provenance, and installed baselines remain unchanged; no global Skill deployment is part of this patch.
