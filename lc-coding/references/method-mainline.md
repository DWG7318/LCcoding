# Method Mainline

```text
Owner Proposal
→ Proposal Readiness Check
→ Project Initialization
→ Calabash Draft
→ [Simulation World foundation first → Workflow capability end ∥ UI product-surface end]
→ Mandatory Calabash Upgrade
→ Product Baseline
→ Feature Slice
→ UI-locked Real Product Integration
→ Independent Verification
→ Owner Acceptance
→ Delivery
```

The bracket is one existing mainline node. Its internal order is: create at least one minimum real, runnable, versioned Simulation foundation; then let Workflow and UI advance independently as equal product ends, each reaching runnable, inspectable results. The node may contain multiple UI, Workflow, and peer Simulation logical subtrees inside one project repository without adding a lifecycle node. The Owner-confirmed Primary product mainline selects the first proving direction; tight cross-layer connection, real integration, and end-to-end proof remain in Feature Slice and UI-locked Real Product Integration.

SLK, CLK, GLK, and other registered execution methods form a separate cross-phase execution-method axis. They are not mainline nodes. Any bounded work item in any phase may select the lightest truthful method and return its evidence to the calling phase.

Operational binding:

- each phase owns its work meaning, evidence sufficiency, and exit gate;
- each selected Loop Run includes D0–D3 and incremental Loop Owner Acceptance without automatically advancing its calling phase;
- after all required third-phase integration work is accepted, Independent Verification performs the centralized vulnerability audit and remediation closure;
- the mainline Owner Acceptance is Post-Security Owner Acceptance;
- Delivery includes customer-specific Delivery Method Q&A before packaging.
