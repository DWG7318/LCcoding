<a id="scope-and-formation-sequence"></a>
## Scope and formation sequence

Source clauses: [LC-FORM-001](../../SPEC.md#lc-form-001), [LC-FORM-003](../../SPEC.md#lc-form-003)

Calabash Draft turns the ready Proposal into working product definition. Mandatory Calabash Upgrade later consolidates Owner decisions before Product Baseline without repeating discovery. Calabash owns definition and Snake/Scorpion consequences; this page does not reproduce its method.

Before actual Workflow or UI construction, establish a minimal, real, runnable, versioned Simulation World foundation. It remains incomplete and `VERSIONED_MUTABLE`. Workflow and UI then advance as equal, independently runnable and inspectable product ends. Cross-layer connection and proof start with Feature Slice.

<a id="peer-product-ends-interfaces-and-mainline"></a>
## Peer product ends, interfaces, and mainline

Source clauses: [LC-FORM-002](../../SPEC.md#lc-form-002), [LC-FORM-003](../../SPEC.md#lc-form-003)

Multiple UI, Workflow, and Simulation units are peer logical subtrees in one project Git/GitHub repository. Each records a safe path, component version, and content hash. Peer Simulation subtrees do not nest; a worktree is optional, not product structure. Stable Map IDs and relations avoid duplicate definitions.

Every CORE and implemented EXTRA Workflow exposes API and MCP contracts backed by the same real capability. The Owner-confirmed Primary product mainline joins one Simulation, CORE Workflow, and UI as the first proving direction without excusing other CORE work. Product Baseline locks the realized set at one exact project commit.

## Scenario and versioned learning

Source clauses: [LC-FORM-001](../../SPEC.md#lc-form-001), [LC-FORM-002](../../SPEC.md#lc-form-002)

Reuse each scenario ID through design, Integration, verification, acceptance, and security evidence. Add fidelity, failure, recovery, or abuse cases as versioned deltas; do not duplicate catalogs or directories. Consequential learning returns through governed Maps and baselines.
