# Simulation World

Product Formation starts with a minimum real, runnable, versioned foundation before actual Workflow or UI construction. The foundation is deliberately incomplete: it is not a one-time complete freeze and remains `VERSIONED_MUTABLE`, gaining realistic actors, states, data, failures, recovery, and new scenarios through versioned deltas.

Once this foundation exists, Workflow and UI can advance independently without early connection or three-way joint integration. Continue semantic and scenario synchronization; Feature Slice and UI-locked Integration retain cross-layer connection and end-to-end proof.

A scenario is defined once and reused through product design, Integration, D0–D3, Loop Owner Acceptance, centralized security threat/abuse review when relevant, and Post-Security Owner Acceptance.

Do not create separate duplicate scenario catalogs when they represent the same product situation. Increase fidelity or add security-specific abuse cases by versioned delta.
